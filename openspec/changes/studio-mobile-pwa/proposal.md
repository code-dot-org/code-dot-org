## Why

Code.org's studio app currently runs only as a Rails-served web app, which assumes a desktop or chromebook with reliable internet. That assumption excludes students in rural and remote classrooms where power is intermittent and connectivity is flaky-to-absent, and it leaves us with no story for iPad or iPhone-only learning environments. This hackathon change reshapes the existing Vite-based `frontend/apps/studio` so the same codebase ships as a Progressive Web App and a Capacitor-wrapped iOS/Android app, with a mobile-first course catalog and at least one fully-offline sample course (AI for Oceans).

## What Changes

- Add a Capacitor shell (`@capacitor/core`, iOS + Android platforms) wrapped around the existing Vite build so the studio app can be packaged as a native mobile binary.
- Configure the studio app as an installable PWA: web app manifest, service worker (via `vite-plugin-pwa`), app icons, offline shell.
- Add a mobile-first course catalog screen that lists course offerings sourced from the Dashboard backend, cached for offline use, and rendered as thumb-reachable tiles with explicit offline/online state badges.
- Pre-bundle one or two sample courses (AI for Oceans is the primary target; a second short Music Lab activity is a stretch) so they launch and run end-to-end with no network — including assets, ML model weights, and student-progress persistence to IndexedDB.
- Add an "offline state" UX model: cached/ready tiles are tappable, online-only tiles are dimmed with a cloud-slash badge, and the app never blocks behind a full-screen offline error.
- **BREAKING for the studio Vite build only**: production build no longer assumes a Rails origin for assets — base path and asset URLs become relative so the same bundle works under `file://` (Capacitor), `/studio/` (PWA), and the existing Rails mount.

## Capabilities

### New Capabilities
- `mobile-shell`: PWA manifest, service worker, install prompts, and Capacitor wrapping of the studio Vite bundle so the same code runs as a web app, an installable PWA, and a native iOS/Android binary.
- `offline-course-catalog`: A mobile-first catalog of code.org courses, fed by the Dashboard backend when online, cached in IndexedDB, and rendered with explicit offline-ready vs needs-network state per tile.
- `offline-sample-course`: Bundle and launch AI for Oceans (and optionally a second short activity) entirely offline — assets, ML model, blockly workspace, and student-progress persistence — with no Dashboard backend round-trip required to play.

## Impact

- **Code**: All changes confined to `frontend/apps/studio/` and (only if strictly required) shared additions to `frontend/packages/oceans-lab` and `frontend/packages/blockly-workspace` to make those packages run with bundled assets and no Rails origin. New top-level `frontend/apps/studio/ios/` and `frontend/apps/studio/android/` directories generated by Capacitor.
- **Dependencies**: Add `@capacitor/core`, `@capacitor/cli`, `@capacitor/ios`, `@capacitor/android`, `vite-plugin-pwa`, `workbox-window`, and `idb` (or `idb-keyval`) to the studio app's package.json.
- **APIs**: Read-only consumption of an existing Dashboard endpoint that lists course offerings (e.g. `/dashboardapi/course_offerings` or equivalent). No new server endpoints in scope; if a suitable endpoint does not exist, we fall back to a bundled JSON snapshot of the catalog.
- **Build**: Vite `base` becomes relative; `vite-plugin-rails` continues to work for local Rails-integrated dev, but a separate `yarn build:mobile` produces a Rails-independent bundle for Capacitor sync.
- **Out of scope** (hackathon discipline): authentication, teacher/classroom sync, leaderboards, progress sync back to Dashboard, App Store / Play Store submission, push notifications, in-app purchases, deep links to Rails routes other than the catalog and bundled courses.
