## ADDED Requirements

### Requirement: Candidate route mounts the read-only home region

The candidate Studio route SHALL mount the read-only home region behind a
`React.lazy` + `<Suspense>` boundary. The route file
`frontend/apps/studio/src/routes/teacher_dashboard/home.tsx` defines the
canonical path `/teacher_dashboard/home` (reached at
`/frontend-studio/teacher_dashboard/home` under the router basepath) and renders
the `@code-dot-org/teacher-dashboard` home component. The route file MUST own
only the route definition and the lazy boundary; all UI, data access, and tests
live in the package. The generated `routeTree.gen.ts` is regenerated by the Vite
plugin and is never edited by hand.

#### Scenario: Route is served under the frontend-studio basepath

- **WHEN** a signed-in teacher navigates to
  `/frontend-studio/teacher_dashboard/home` in a preprod or local environment
- **THEN** the teacher-dashboard home component mounts inside the Studio shell
- **AND** the URL retains underscores (`/teacher_dashboard/home`) while the
  package name uses hyphens (`teacher-dashboard`)

### Requirement: Sections are read through the typed DashboardApiClient

The home region SHALL obtain its section data exclusively through
`DashboardApiClient.sections` calling `GET /api/v1/sections`. A new list method
SHALL parse the response with a new zod schema modeling
`summarize_without_students`; the existing `ConciseSectionSchema` (which models
the different `concise_summarize` payload) SHALL NOT be reused. No hand-rolled
`fetch`/`ky` call to the backend is permitted. The schema camelCases snake_cased
wire keys at the boundary and validates the fields the UI consumes.

#### Scenario: Response is parsed and validated at the boundary

- **WHEN** `GET /api/v1/sections` returns a 200 JSON array of section summaries
- **THEN** the client parses each element through the new schema and returns
  typed, camelCased section objects
- **AND** a response element missing a required consumed field (e.g. `id` or
  `name`) causes the parser to reject rather than render undefined data

### Requirement: Empty home region for a teacher with zero sections

WHEN a signed-in teacher instructs zero sections, the candidate SHALL render an
empty-state region equivalent to the legacy `EmptyHomepage`
(`apps/src/templates/studioHomepages/teacherHomepageV2/EmptyHomepage.tsx`): a
headline, a description, and an illustrative image, built from design-system
components. No section cards are rendered.

#### Scenario: TD-HOME-EMPTY — zero-section teacher sees the empty state

- **WHEN** a signed-in teacher with zero sections loads the candidate route
- **AND** `GET /api/v1/sections` returns `[]`
- **THEN** the empty-state headline, description, and image render
- **AND** no section card or section list is present in the DOM
- **AND** the region passes a scoped axe check and exposes a single logical
  heading for the region

### Requirement: Populated home region renders read-only section cards

WHEN a signed-in teacher instructs one or more sections, the candidate SHALL
render a read-only list of section cards equivalent to the legacy `SectionList`
/ `SectionCard` region. Each card SHALL display the section name, join code,
student count, and — when the section is assigned to a course — the assigned
course display name; and SHALL render an unassigned affordance when no course is
assigned. The pilot renders these as read-only labels: no create/edit/archive/
delete, no drag reorder, no add-students, no course-assignment, and no
progress/roster/materials/settings actions are wired.

#### Scenario: TD-HOME-SECTION-LIST — two sections, one assigned, render read-only

- **WHEN** a signed-in teacher instructs exactly two student sections — one with
  no course assignment, one assigned to `ui-test-single-unit-course-2026` unit 1
  with one joined student
- **AND** `GET /api/v1/sections` returns the two corresponding summaries
- **THEN** two section cards render in the list region
- **AND** the assigned card shows the course display name for
  `ui-test-single-unit-course-2026` and a student count of 1
- **AND** the unassigned card shows its unassigned affordance and a student count
  of 0
- **AND** no mutating control (create/edit/archive/delete/reorder/add-students/
  assign-course) is present or wired
- **AND** the region passes a scoped axe check and is fully keyboard reachable
  with a visible focus indicator
