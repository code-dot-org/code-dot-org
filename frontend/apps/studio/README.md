# Code Studio (Experimental)

Studio is the experimental host React application for Code.org's frontend — curriculum labs, teacher tools, and other Code.org features. It is served at `/frontend-studio/` in both modes (see below) and is not a library package; it has no exports and is never imported by other packages. The current frontend is called `apps` and is located in the root directory.

## Dev setup

Two modes are available, both served at the same `/frontend-studio/` URL prefix:

**Vite Rails (preferred)** — Rails serves the app with Vite proxying assets. Access at `http://localhost-studio.code.org:3000/frontend-studio/`. Requires Rails running (see repo root `README.md`), then from `frontend/`:

```bash
yarn dev
```

**Standalone** — Vite serves the app directly, without Rails. Access at `http://localhost:3036/frontend-studio/`. Useful for frontend-only work that doesn't require a live backend.

```bash
yarn dev   # same command — standalone when Rails is not running
```

Standalone mode is supported by design: Studio is architected to be independently deployable and testable from the backend.

## Routes

Routes are file-based under `src/routes/` using TanStack Router. Read `src/routeTree.gen.ts` or the files in `src/routes/` directly to see current routes — enumerating them here would go stale.

The route tree (`src/routeTree.gen.ts`) is auto-generated by the TanStack Router Vite plugin — do not edit it by hand.

Route definitions use canonical paths (e.g. `/projects/$labType/$channelId/edit`); the router prepends `/frontend-studio` automatically at link-construction time and strips it during URL matching. The same prefix is used by:

- Rails: `get "frontend-studio(/*path)"` in `dashboard/config/routes.rb` catches SPA routes and serves the Haml shell.
- Vite: `config/vite.json`'s `publicOutputDir: "frontend-studio"` makes `vite-plugin-ruby` set Vite's `base` to `/frontend-studio/`, so both the dev server and the production build live under that prefix.

## Adding a lab

See `frontend/docs/conventions/packages.md` (the `## Labs` section) for the full scaffolding steps. The short version — two Studio files must be updated:

- `src/modules/labs/config/labs.ts` — add the lab key to `AVAILABLE_LABS`
- `src/modules/labs/router/getLabEntrypoint.ts` — add the lazy import to `LabEntrypoints`
