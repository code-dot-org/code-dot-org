## Observed patterns

1. Title grammar splits by site register: GitHub and MDN guides use gerunds ("Changing your username," "Using promises"); Microsoft, GOV.UK, Google, GitLab (task subsections), and Stripe use bare imperatives ("Change your password," "Set up the customer portal"); Microsoft and the two Zendesk help centers also use literal questions ("How to change...," "How do I change my username?"); MDN reference and GitLab's omnibus page use plain nouns ("Array.prototype.map()," "Two-factor authentication," "Profile preferences").
2. Every account-settings page that has a why/when sentence puts it before the first step, never after: GitHub's Prerequisites, Microsoft's "known vs. forgotten password" distinction, Google's cooldown note, GitLab's 2FA lockout risk, Stripe's "when you're ready to..." line.
3. Two of nine non-Stripe/MDN pages skip numbered steps entirely and instead hand off to a single UI action link (Microsoft name/address page: "Edit name"/"Edit addresses"; GOV.UK driving-licence page: bullets, not numbers).
4. GOV.UK is the only site that names steps as literal "Step 1/2/3" H2s on the page itself (tell-dvla-changed-address); everyone else keeps step numbers inside a numbered-list widget under a topic-named H2.
5. Platform/device variants are handled as top-level tabs on Microsoft (Desktop/iOS/Android) and Google (Computer/Android/iPhone & iPad) pages, but as prose "If you..." subsections on GOV.UK and as separate page-variant URLs (a chooser index) on Stripe — no site mixes tabs and prose-conditionals on the same page.
6. Screenshots/UI-element images, when present, sit inline at the specific step they illustrate (GitHub's "New repository" dropdown at step 1, Google's Join-class-button icon, Microsoft's upload/delete icons) — none of the sampled pages front-load a hero image before the steps.
7. GOV.UK and GitLab are the only sites where a single task page ends purely with a lightweight feedback widget ("Is this page useful?" / none) rather than a curated links list; GitHub, Microsoft, Google, and MDN all close with a named links section (Next steps / See also / Need more help? / Related resources).
8. "Account settings" pages are markedly more likely to omit numbered steps than "how do I do X with a class/document/payment" pages in the same sample: Microsoft name/address (0 steps), GOV.UK name-on-licence (0, bullets), Google edit-name (0 captured) vs. GitHub username (6), GitLab username (5), Google Classroom join-code (4), Stripe portal (3).
9. Reference-style pages (MDN Array.map, GitLab's two big omnibus profile pages) front-load a syntax/definition block before any narrative, where task-style pages front-load a one-line statement of the goal ("Securely accept payments online," "Change your GitHub username").
10. Every task page in the sample that discusses optional/advanced work marks it explicitly rather than folding it into the main sequence: GitHub's "Optional, in the Description field," Stripe's "Optional:" H2 prefix twice, GOV.UK's "If you want to change your photo at the same time" subsection.
11. None of the 19 directly-fetched pages used a data table to present step variants; tables in this sample are reserved for reference data (Stripe's test-card numbers, GitLab's tier-availability note) rather than for procedural options.
12. The two pages that most resemble each other in the whole sample are GOV.UK's tell-dvla-changed-address and Stripe's no-code/customer-portal: both open with a plain-language why sentence, both number top-level H2s as sequential named actions, both put "optional" work after the required core.

## Where sites differ

- Multi-page pagination: only GOV.UK splits one task across multiple URLs with "Next:" navigation (renew-adult-passport); every other site keeps a task on one page, even when long (GitLab's 2FA page has 18 H2s on one URL).
- Omnibus vs. atomic pages: GitLab's account-settings content lives on two very large reference-shaped pages (26 H2s, 18 H2s) that bundle dozens of unrelated settings, whereas GitHub, Microsoft, Google, and GOV.UK each give account-settings tasks their own single-purpose URL.
- Variant mechanism: Stripe uses URL-parameter–driven page variants selected from an index (no client-side tabs visible in fetched markdown); Microsoft and Google use visible in-page tabs; GOV.UK uses inline "If you..." prose sections; GitHub uses branching within a single numbered step.
- Legal/civic content (GOV.UK) states costs, statutory deadlines, and penalties inline ("£102... £115.50," "fined up to £1,000") that no other site's task pages include.
- Age/guardian-gated variants appear only in the K-12 sample (Khan Academy's 13+ self-serve vs. parent-managed usernames), not in any general-audience site fetched.
- Ending style: GitHub/Microsoft/Google/MDN close with a curated links section; GOV.UK and GitLab close with feedback/TOC widgets instead; Stripe's customer-portal page has no closing section at all, it simply stops after the last optional subsection.
- Image density: Microsoft and Google pages use small inline icons throughout; GitHub uses full annotated screenshots but sparingly (one per page); GOV.UK, GitLab (mostly), MDN, and Stripe use none, substituting code blocks (Stripe) or bare prose (GOV.UK, MDN) for what other sites show as a picture.
